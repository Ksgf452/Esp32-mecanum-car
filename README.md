# 四麦轮小车 · ESP32 + ESP-NOW + MPU6050

基于两块 ESP32 的四麦轮全向小车。遥控端读取双摇杆，经 **ESP-NOW** 点对点发送到车载端；车载端执行麦轮逆运动学，并用 **MPU6050 偏航角速度闭环** 抑制平移跑偏。

**无需路由器、无需配网**，上电即连。实测端到端延迟约 10ms。

---

## 1. 功能

| 操作 | 功能 |
|---|---|
| 左摇杆 左右 | 原地顺时针 / 逆时针旋转 |
| 左摇杆 上下 | LED 亮度 |
| 右摇杆 上下 | 前进 / 后退 |
| 右摇杆 左右 | 右平移 / 左平移 |

- **失联保护**：遥控端断连或超出范围 500ms，车载端自动停车。
- **偏航闭环**：平移时 MPU6050 检测车头偏转，PID 输出反向旋转补偿，抑制因四轮摩擦不均导致的跑偏。
- **上电安全**：车载端未收到首帧数据前保持停车，不会因摇杆数据全 0 而误动作。

## 5. 烧录步骤

### 5.1 先烧车载端，获取 MAC

1. 打开 `vehicle/vehicle.ino`，烧录到车载端 ESP32。
2. 打开串口监视器（115200），等待初始化完成，记录打印的 MAC，例如：
   ```
   [车载端] 真实 MAC: 38:3E:51:58:1F:94
   [车载端] 就绪，等待遥控数据...
   ```

### 5.2 把 MAC 填入遥控端

打开 `remote/remote.ino`，修改：

```cpp
uint8_t carMAC[] = {0x38, 0x3E, 0x51, 0x58, 0x1F, 0x94};
```

逐字节对应 `38:3E:51:58:1F:94` → `{0x38,0x3E,0x51,0x58,0x1F,0x94}`。

### 5.3 烧录遥控端

烧录后串口应打印：

```
[遥控端] peer 注册成功
[遥控端] 本机 MAC: XX:XX:XX:XX:XX:XX
[遥控端] 就绪，开始发送
```

### 5.4 验证链路

车载端串口出现：

```
[车载端] 已收到首帧遥控数据
```

即链路打通，推摇杆电机响应。

## 6. 运动学校准说明

本项目采用 **X 型辊子布局**（辊子轴线向外呈 X 形）。逆运动学公式为：

```
wFL = vx - vy + w·K
wFR = vx - vy - w·K
wBL = vx + vy + w·K
wBR = vx + vy - w·K
```

其中：
- `vx` 前进分量（代码中已取反 `-forward`，适配实际电机接线）
- `vy` 平移分量（`strafe`，右移为正）
- `w` 旋转分量（代码中已取反 `-rotate`，适配实际转向）
- `K = ROTATE_GAIN`（默认 1.0）

**X 型布局的平移特征**：右移时**前轮反转、后轮正转**；左移反之。若你的轮子实际是 **O 型布局**（对角线同向），需把 `vy` 相关项符号取反：

```cpp
float wFL = vx + vy + w * K;
float wFR = vx - vy - w * K;
float wBL = vx - vy + w * K;
float wBR = vx + vy - w * K;
```

**单轮方向校准**：若某个轮子转向与预期相反，只需把 `MOTOR_DIR` 对应位置改为 `-1`，不必交换电机线：

```cpp
// FL, FR, BL, BR
int8_t MOTOR_DIR[4] = {+1, +1, +1, +1};
```

## 7. 偏航 PID 调参指南

### 7.1 原理

平移时四轮摩擦不均会合成偏转力矩。MPU6050 测量偏航角速度，期望值为 **0**，PID 输出一个反向旋转补偿叠加到 `rotate` 通道，主动抵消跑偏。

```
rotate_final = rotate_user + PID(0 - gyroZ)
```

### 7.2 调参顺序（务必按序）

**第 0 步：确认零偏校准有效。**
上电时小车必须**完全静止放平**。串口会打印 `陀螺仪零偏: X.XXX °/s`。之后不做任何操作，看调试打印 `gyro=` 一栏，应稳定在 **±0.5°/s 以内**。噪声大或漂移明显，检查 MPU6050 是否固定牢固、I2C 线是否过长。

**第 1 步：只开 P。**
保持 `yawKi=0, yawKd=0`，`yawKp=1.0`。推右摇杆做纯横向平移：
- 车头仍持续偏转 → `yawKp` 加到 1.5、2.0；
- 车头被抑制但有**低频左右摇摆** → `yawKp` 减到 0.6、0.5；
- 找到“偏转明显被压住、几乎不摇摆”的值。

**第 2 步：加一点 I。**
`yawKi` 从 0.1 起，每次加 0.1。I 消除 P 抑制后的缓慢偏转趋势。**若车头开始缓慢“游走”或摆动，说明 Ki 过大，退回去。**

**第 3 步：最后加 D。**
`yawKd` 从 0.05 起。D 压制 P 的过冲。**若电机出现高频抖动，立即降回或归零。**

**第 4 步：看补偿限幅。**
调试打印 `comp=` 一栏，纯平移时应看到明显非零值在对抗偏转。若长期贴到 `±300` 限幅，说明 Kp 偏小或机械偏差过大（重心偏置、轮子摩擦异常），应先做机械检查，不要一味加大 `YAW_CORRECTION_LIMIT`。

### 7.3 极性检查

烧录后先做纯平移测试：

- **车头偏转被抑制、松手能自己回正** → 极性正确；
- **车头摆动越来越大（正反馈）** → 把 `computeYawCorrection()` 的 `return` 改回 `constrain(correction, ...)`。

### 7.4 机械前提

调 PID 前先做机械检查：**把小车放水平面，从四个方向轻按车身，感受四轮着地力是否均匀**。重心偏置会让一侧正压力天然更大，这是 PID 需要“用力”对抗的根源。优先把电池等重物移到几何中心附近。

## 8. 调试输出说明

### 遥控端

```
LX=2048 LY=2048 RX=2048 RY=2048
```

推摇杆时对应值变化。若某个轴始终 2048 不变，检查该轴接线或摇杆硬件。

### 车载端

```
LX=2048 RY=3000 RX=2048 | fwd=465 str=0 rot_u=0 comp=-23 rot_f=-23 gyro=0.4
```

| 字段 | 含义 |
|---|---|
| `LX/RY/RX` | 原始 ADC 值 |
| `fwd/str` | 前进 / 平移指令 |
| `rot_u` | 摇杆旋转指令 |
| `comp` | PID 偏航补偿量 |
| `rot_f` | 最终旋转指令 |
| `gyro` | 实测偏航角速度（°/s） |

## 9. 常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 上电某两个轮狂转 | 初始 `rxData` 为 0 被当成摇杆打满 | 已修复：初始化为中位 + `hasReceived` 保护 |
| 车载端 MAC 打印全零 | `WiFi.macAddress()` 接口未就绪 | 已修复：改用 `esp_read_mac()` |
| 遥控端发送成功但车载端收不到 | 两端信道不一致 / peer channel 硬编码 | 已修复：两端 `esp_wifi_set_channel(1, ...)`，peer `channel=0` |
| 左摇杆旋转无反应 | 旋转项乘米制 `K` 被压到 14% | 已修复：改用无量纲 `ROTATE_GAIN=1.0` |
| 平移方向与预期相反 | O 型 / X 型辊子布局差异 | 已按 X 型校准；O 型需翻转 `vy` 项符号 |
| 前进/旋转方向反 | 电机物理接线方向 | 已通过 `vx=-forward`、`w=-rotate` 校准 |
| PID 补偿导致摆动加剧 | 反馈极性反 | 把 `computeYawCorrection` 的 `return` 改回 `constrain(correction, ...)` |
| 编译报 `ledcAttachChannel` 未定义 | 使用 Core 2.x | 改用 `ledcSetup` + `ledcAttachPin` |
